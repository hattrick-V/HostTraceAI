# 调查编排（主机溯源）

本技能规定"一次溯源调查怎么推进"：顺序、判据、停止点、分派点与交付物。具体命令在专门技能里（`windows-host-triage`、`windows-forensic-timeline`、`webroot-forensics` 等）；本技能只管**流程与判据**。

## 适用条件

- 接到主机失陷线索：安全设备通报外联、用户报告电脑异常、业务主机 CPU/带宽异常、Web 站点被挂后门、勒索加密、账号被盗用。
- 已有目标主机的 IP/主机名，通常还有连接方式（主机通道/SSH/MCP）与凭据来源。
- 需要回答的问题通常是四选一：**是不是失陷**、**什么时候怎么进来的**、**影响了什么**、**怎么处置干净**。

缺少以下信息时**先补齐再动手**，否则调查会反复：目标主机标识与归属（谁在用、学号/工号）、症状与首次发现时间、业务影响与允许操作窗口、可用凭据与连接方式、是否有第二个受害主机（同活动多机同时排查更省事）。

## 证据要求

- **每个动作都要落盘**：主机标识、采集时间（含时区）、执行命令原文、原始输出、文件路径、SHA-256、来源可信度。
- **原始优先**：保留命令原始输出文本，不要只写"检查后发现…"；日志引用保留行号区间。
- **时间统一**：Windows 事件日志/注册表时间注意 UTC 与本地时间差异；把多主机时间线换算到同一时区后统一排序。
- **三角验证**：一个结论至少两条独立证据（例：文件哈希 + 持久化项 + 外联记录），否则标"待验证"。
- **样本先归档**：任何移动/清理前，先把候选文件只读复制并生成 SHA-256 清单；处置后核对副本仍可还原。

## 工具顺序

1. **接案定界**（10 分钟内完成）
   - 记录：主机、归属人、症状、时间窗、连接方式、允许的操作窗口。
   - 环境基线：主机名、系统版本、启动时间、当前时间与时区、当前账号权限。
2. **只读采集（按此顺序，每层做完再进下一层）**
   1. 进程与父子关系（含命令行、路径、创建时间）；
   2. 网络连接与监听端口（PID 关联进程）；
   3. 服务、驱动、启动项、计划任务（含 WMI 事件订阅）；
   4. 账号与登录记录（新增账号、异常登录、提权痕迹）；
   5. 文件与样本（按落地时间窗筛，算哈希、看签名与版本信息）；
   6. 日志与痕迹（安全/系统/应用日志、DNS 缓存、下载记录、浏览器痕迹）；
   7. 反取证核验（日志是否被清、安全软件是否被卸载/接管、代码完整性策略是否被改）。
3. **假设验证**：对每个候选结论列出"支持证据 / 反对证据 / 缺失证据"，缺证据就去补采集，而不是下结论。
4. **时间线重建**：投毒载体（下载/上传/邮件/U 盘/共享）→ 文件释放 → 持久化 → 外联 → 后续动作（横向、加密、外传），每个时间点标注证据与置信度。
5. **分派专家**（见下）。
6. **处置编排**：按"先止损、再清除、后修复、最后复验"排序；每条动作写命令、影响面、回滚方式，提交审批后执行。
7. **闭环复验**：处置后重采一遍（进程/持久化/外联/安全软件状态），确认木马不再运行、持久化已清、安全软件能正常装上。
8. **结案**：加载 `trace-report-and-evidence-chain` 出报告。

## 分派点判据

| 证据指向 | 分派给 | 交付内容 |
| --- | --- | --- |
| 进程/服务/驱动/计划任务/样本/外联/挖矿/远控 | `malware-triage` 病毒木马溯源专家 | 家族或类型、落地时间、持久化方式、外联目标、样本哈希 |
| Web 目录/脚本改动/上传目录/访问日志/Web 进程子进程 | `webshell-triage` WebShell 后门溯源专家 | 后门清单、入口推断、来源 IP、时间线、影响面 |
| 内存线索（隐藏进程、注入、无文件） | 加载 `memory-forensics` 后由 `malware-triage` 继续 | 内存证据与时序 |
| 外联流量特征/C2 心跳 | 加载 `pcap-traffic-analysis` 后由 `malware-triage` 继续 | C2 目标、协议特征、数据外传量 |

分派时必须写清：目标主机与连接方式、时间窗、**已知事实（含证据路径与哈希）**、要回答的问题、红线、期望输出格式。上下文缺失会让专家重复采集。

## 停止条件

- 达成当前阶段目标（定性/定时/定范围）→ 进入下一阶段，不要在同一层无限深挖。
- 需要处置动作、跨主机/跨网段、需要业务停机、缺凭据或权限 → 停下，提交审批或升级给人类负责人。
- 连续两轮采集无新增证据 → 停止并如实标注"证据边界"。
- 采集可能影响业务（全盘遍历、大文件传输、高开销查询）→ 先申请时间窗，不要直接跑。

## 输出格式

每轮汇报（写给人类负责人看）：

```
【目标主机】<ip/主机名> <归属人/学号> 连接方式 <…>
【本轮目标】一句话
【已知事实】- …（证据：路径/命令/哈希）
【推断】- …（置信度 高/中/低，依据）
【待验证】- …
【已固化证据】<证据包路径> / <SHA-256>
【下一步】动作 + 理由（或：需审批的处置项 + 影响 + 回滚）
```

结案产出：**落地时间线表**（时间 → 事件 → 证据 → 置信度）、**IOC 表**（类型/值/首次出现/来源）、**处置项清单**（待审批/已执行/已回滚）、**证据索引**（每条证据的路径 + SHA-256）、**未决问题与建议**。

## 红线与审批

- 只读动作（读进程/服务/注册表/日志/文件属性、算哈希、导出副本）直接做，不请示。
- 处置动作（终止进程、禁用服务/驱动/账号、隔离主机、阻断外联、下载或隔离样本、改注册表/策略）**必须先出方案并走审批**：命令 + 影响面 + 回滚方式。
- 禁止：删除非恶意文件；销毁样本；口令尝试/爆破；对非目标主机的连接与扫描；把证据外发到平台与授权分析机之外。
- 任何"以风险为由拒绝"的做法都不可接受——正确姿势是给出风险、影响与可控替代方案。
