# 判断“入侵 IP / 外联地址是否可得”（Windows 主机侧口径）

用户问“日志里能不能知道入侵 IP / 攻击者从哪来”时：**先穷举证明主机侧是否有带源地址的记录，再给结论**，不要凭印象答“没查到”。本文件配合 `windows-forensic-timeline` 主文件使用。

## 1. 有源 IP 的记录（就这么几类）

| 来源 | 字段 / 事件 | 备注 |
|---|---|---|
| Security 4624 / 4625 | “源网络地址”“工作站名” | **只有登录类型 3（网络）、10（RDP/RemoteInteractive）、8（网络明文）带真实地址**；类型 5（服务）、2（控制台）恒为 `-` |
| Security 5156 / 5157（WFP 连接审计） | 五元组 | 默认关闭；且属 Security 日志，被清则无 |
| Security 5140 / 5145（共享访问） | 网络地址 | 需先开启对象访问审计 |
| RDP 通道 | `RdpCoreTS` 131（服务器已接受来自客户端 X:port）、`RemoteConnectionManager` 261/1149 | **261 是“侦听程序已收到连接”，1149 本身不带 IP**；需与 131/1149 按秒对齐才能得到“IP + 用户 + 成功/失败” |
| SMB 通道 | `Microsoft-Windows-SMBServer/SmbClient Security` | 多为空，需审计开启 |
| 应用日志 | IIS 访问日志 `c-ip`、MSSQL ERRORLOG `[CLIENT: x.x.x.x]` | **主机侧最可能拿到 IP 的地方**，但常不在现成采集包里，要单独索取 |
| 安全软件日志 | 国产 AV/EDR 的防护/拦截日志 | 常记连接与拦截五元组；服务被杀/崩溃**之前**的日志尤其值钱 |
| SRUM（`SRUDB.dat`） | 每进程网络用量（30~60 天） | 只有字节数与进程，无对端地址，可作为“有过外联”的旁证 |

## 2. 拿不到 IP 的记录（别浪费时间）

- **Windows 防火墙通道**：只有 2002/2003/2004/2005/2006/2010/2011 这类规则变更/配置文件切换/提示事件，**不含成功连接的五元组**。
- **远控软件（ToDesk、向日葵等）**：日志只出现中转/中心服务器地址（厂商自己云节点），对端真实 IP 不外露，只暴露设备 ID。
- **采集包的 `sockets` / `arp_table` / `netuse` / `rdp_connect_*`**：全是**采集时刻的瞬时快照**，攻击者早已离开；只有 `dns_caches` 偶尔还能留到前一晚的解析记录，值得瞄一眼。
- NTFS / Store / AppReadiness / DeviceSetupManager / BITS 等通道：无网络字段。

## 3. 结论怎么写（口径）

1. **先穷举后断言**：把目标时间窗的全部相关通道导出文本，按日期过滤并提取 IP 去重：

   ```
   grep -hE '^<YYYY-MM-DD>' *.txt | grep -oE '([0-9]{1,3}\.){3}[0-9]{1,3}' | sort -u
   ```

   注意误命中：版本号（如 `8.0.8.1636`）、`0.0.0.0`、子网掩码都不是来源地址。
2. 报告写法：**“主机侧无任何带源地址的网络登录记录（无 RDP/SMB 入站会话；Security 日志被清；防火墙不记录连接级）”**，而不是含糊的“没查到 IP”。
3. 把可推得的结论一并给出：**若事件当天主机侧完全没有网络登录，说明当天只发生了执行/加密动作，入口不一定在当天** → 取证时间窗要往回拉（回溯到上一次正常状态/最近一次正常备份）。

## 4. 补证路径（按性价比排序）

1. **边界设备**（防火墙 / IPS / NTA / 上网行为管理）→ 目标窗口内到受害主机的入站五元组；窗口按 §3.3 拉长。
2. **远控平台云端**（ToDesk 等）→ 该设备 ID 的“最近连接/被控记录”（含控制端 ID + 时间 + IP），与本地服务日志交叉验证“某天到底有没有会话”。
3. **主机上未被采集的应用/安全日志**：IIS 访问日志、MSSQL ERRORLOG、国产 AV/EDR 防护日志。
4. 采集包解密后的网络类 JSON（瞬时快照，价值有限）。
