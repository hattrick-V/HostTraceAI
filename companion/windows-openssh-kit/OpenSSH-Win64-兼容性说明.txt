OpenSSH-Win64 溯源用 SSH 临时启用工具 —— 兼容性说明
======================================================

一、为什么这里放了三套 OpenSSH
------------------------------------------------------------------------
现象: 把上游 Win32-OpenSSH 丢到老服务器上, 安装、启动服务全部"无报错",
      但客户端一连就报:
          Connection reset by <IP> port 22
      用 ssh -vvv 看, 已经收到服务器横幅(SSH-2.0-OpenSSH_for_Windows_10.0 ...),
      客户端发完 KEXINIT 之后才被 reset。

原因: OpenSSH 9.8 以后 sshd 被拆成 sshd.exe(监听) + sshd-session.exe(会话):
      sshd.exe 能在老系统上跑起来, 所以"服务是 RUNNING、端口能连、横幅能出",
      但负责密钥交换的会话子进程在新系统 API 缺失时会被直接干掉,
      结果就是 22 端口通、协议走两步就断。上游标明 9.8/10.x 需要
      Windows 10 1809+ / Windows Server 2019+。
      另外官方要求: 程序目录必须只有 SYSTEM/管理员可写, 否则也会出现同样的
      reset(把 OpenSSH 放在桌面、下载目录、U 盘里就属于这种情况)。

二、本工具的做法
------------------------------------------------------------------------
bin\ 下放了三套上游原版程序(文件未做任何改动):
    bin\7.7.2.0    v7.7.2.0p1-Beta   老架构(单进程 sshd), 兼容 Win7/2008R2/2012/2012R2/2016
    bin\8.9.1.0    v8.9.1.0p1-Beta   折中版本
    bin\10.0.0.0   10.0.0.0p2-Preview 最新, 需 Win10 1809+ / Server 2019+

1-启用SSH.bat 会:
  1) 读系统 build 号, 生成版本尝试顺序
       build >= 17763 (Win10 1809+ / Server 2019 / 11 / 2022): 10.0.0.0 -> 8.9.1.0 -> 7.7.2.0
       build <  17763 (Win7 / 8 / 8.1 / 2012 / 2012R2 / 2016)  : 7.7.2.0 -> 8.9.1.0 -> 10.0.0.0
  2) 把该版本复制到 C:\Program Files\OpenSSH-Win64, 并收紧目录权限
       (SYSTEM/管理员可写, Authenticated Users 只读+执行; 用 SID 授权, 不受中英文系统影响)
  3) 生成主机密钥、写 sshd_config、安装 sshd 服务
  4) 用回环 ssh-keyscan 做真实密钥交换自测; 拿不到主机公钥 = 该版本不可用, 自动换下一套重试
  5) 三套都失败时, 自动跑 sshd -ddd 并把调试输出打到屏幕上
  6) 放行防火墙端口(默认 22)

三、系统对照表
------------------------------------------------------------------------
    Windows Server 2012 / 2012 R2    build 9200 / 9600    默认用 7.7.2.0
    Windows Server 2016              build 14393           默认用 7.7.2.0
    Windows Server 2019              build 17763           默认用 10.0.0.0
    Windows 10 / 11                  build 19041+ / 22000+ 默认用 10.0.0.0
    Windows 7 / Server 2008 R2       build 7601            默认用 7.7.2.0,
                                                          需先装 KB2999226(通用 C 运行库)
    上表只是默认顺序, 实际以脚本自测结果为准(不通就自动换版本)。

四、用法
------------------------------------------------------------------------
  1) 把整个 OpenSSH-Win64 文件夹拷到目标机(放哪都行, 脚本会自己装到 Program Files)
  2) 管理员运行 1-启用SSH.bat
  3) 溯源结束运行 2-停止卸载.bat
     (停服务、还原或清理配置、删掉装进 Program Files 的那个目录)

  可选环境变量:
    SSH_TRACE_PW=密码            免交互设置 administrator 密码
    SSH_TRACE_PORT=2222          换端口
    SSH_TRACE_INSTDIR=D:\OpenSSH 换安装目录
    SSH_TRACE_FORCE_INSTALL=1    机器上原本有别人装的 sshd 时, 强制用本工具的程序接管
    SSH_TRACE_FAKEBUILD=9600     人工指定版本阶梯(调试用)

五、排错
------------------------------------------------------------------------
  1) 日志: 本目录 ssh-trace.log; 服务状态: sc query sshd
  2) 手工前台调试(能看到最原始的报错):
       cd /d "C:\Program Files\OpenSSH-Win64"
       sshd.exe -ddd -f "%ProgramData%\ssh\sshd_config"
     然后在别的机器上连本机 22 端口, 看这个窗口刷出来的内容
  3) 手工判断服务是不是"活的"(端口通不代表活):
       bin\7.7.2.0\ssh-keyscan.exe -T 8 -t rsa,ed25519 127.0.0.1
     打印 "127.0.0.1 ssh-ed25519 AAAA..." = 正常
     只打印 "# 127.0.0.1:22 SSH-2.0-..."    = 服务在但会话子进程起不来(就是 reset 那个病)
  4) 22 端口是否被别的程序占用: netstat -ano | findstr :22
